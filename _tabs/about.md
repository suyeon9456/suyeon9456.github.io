##### 문제 상황
기존에는 예기치 못한 오류가 발생하면 서버 로그를 확인해, API 요청 및 응답 상태를 확인하거나 사용자에게 개발자 도구 콘솔에 표시되는 오류 메시지 스크린샷을 요청하는 등 불편함이 있었습니다. 이러한 방식은 오류 상황을 신속히 확인하기 어렵게 만들었으며, 문제 해결이 지연되는 동안 동일한 오류를 겪는 사용자가 증가하는 문제로 이어졌습니다.

클라우드 기반 Sentry를 사용할 수도 있었지만, 비용 절감 및 데이터 보안을 위해 온프레미스(On-Premise) 방식으로 Sentry 서버를 구축하였습니다. 이를 통해 데이터가 외부로 유출되지 않도록 보호하고, 내부 네트워크에서만 접근할 수 있도록 설정했습니다.

또한, beforeSend 기능을 활용하여 긴급도나 중요도가 높은 오류 로그만 필터링해 Sentry로 전송하고, 샘플링을 적용해 트래픽을 효율적으로 관리할 수 있도록 했습니다. 더불어, 운영 환경에서 발생하는 오류를 신속히 분석할 수 있도록 소스맵(Source Map)을 제공하여 개발자 경험(DX)을 개선했으며, 오류 발생 시 슬랙(Slack) 알림 시스템을 통해 실시간으로 대응할 수 있도록 설정했습니다.

- 문제 해결 시간 단축
- 사용자 경험(UX) 및 개발자 경험(DX) 향상

### **Next.js 버전 업그레이드 주도**
##### 개요 
기존의 사용자별 뉴스레터 아카이빙 페이지는 Next.js 12 버전으로 운영되고 있었지만, **최신 기술 도입과 장기적인 유지보수**를 위해 Next.js 14 버전으로 업그레이드가 필요하다고 판단했습니다. 업그레이드를 통해 기대할 수 있는 개선 사항들을 정리해, 팀에 제안 하였고 제안이 수용된 이후에는 **프로젝트의 버전 업그레이드를 주도**하며 그간 개선이 필요했지만 시간적인 문제로 진행하지 않았던 배포 환경 통일 등 개선 사항들을 함께 진행하게 되었습니다.

##### 개선 사항
**Next.js 14 버전 업그레이드**
- App Router 전환 및 layout 활용 → 변동 적은 데이터 처리 최적화
    - 코드 중복과 감소
- 상호작용이 필요한 컴포넌트를 제외한 나머지 부분을 서버 컴포넌트로 생성
    - 클라이언트로 전송되는 JavaScript의 양을 최소화 -> 초기 로딩 속도 빨라짐
- 메타데이터 선언적 관리 → Metadata API 도입
- 서브 도메인과 사용자의 뉴스레터 주소록 매칭을 Next.js middleware를 사용해 처리

**웹 접근성 개선**
- Next.js 내장 컴포넌트 적극 활용
- 시멘틱 태그로 마크업 개선
- eslint-plugin-jsx-a11y 추가 → 개발 단계에서 접근성 문제 확인 가능

**상태 관리 라이브러리 전환**
- 기존: Redux → 전환: Zustand
    - 보일러플레이트 코드 감소, 가독성 및 유지보수성 향상

**배포 환경 통일**
- 기존 QA: EC2 + PM2 / 운영: Docker + AWS ECS
    - 환경 불일치로 인한 의도하지 않은 운영 버그 발생
- 변경: QA도 Docker + ECS 기반으로 통일
    - 환경 불일치 해소, 운영/QA 간 동일한 배포 파이프라인 확보

**기술적 문제 해결**
- React 18 도입 시, 모노레포 환경의 다중 React 버전 문제 해결

##### 성과

### **정산 프로세스 자동화 기능 기획 및 개발**
##### 개요
기존 운영팀은 유료 뉴스레터를 운영하는 사용자에게 정산서를 발급하기 위해, 구글 시트를 활용해 정산 데이터를 수기로 관리하고 개별적으로 메일을 발송하는 방식으로 업무를 진행하고 있었습니다. 이 과정을 효율적으로 진행할 수 있도록 **백오피스에 해당 업무를 자동화할 수 있는 기능을 기획하고 UI 설계 및 개발까지 전담**하여 구현하였습니다.

##### 진행 과정
백오피스의 주요 사용자인 운영팀과의 논의를 통해 요구사항을 상세히 분석한 뒤, 업무 흐름을 시각적으로 정리하고 이를 기반으로 피그마를 활용해 UI를 설계했습니다. 설계된 UI는 운영팀과 공유하며 피드백을 적극적으로 반영했으며, 백엔드 개발자와 협력해 필요한 API를 정의하고 구현했습니다.

##### 구현 내용
백오피스에서 정산 데이터를 관리할 수 있도록 수정/추가/삭제 기능 추가했으며, 미지급 상태의 사용자의 경우에도 별도로 관리할 수 있는 기능을 구현했습니다. 일일이 생성하고 발송하던 정산서를 각각의 결제 내역에 맞게 생성하여 일괄 발송이 가능하도록 하였으며 메일이 모두 발송되면 슬랙으로 노티되는 기능을 추가했습니다.

##### 성과 및 효과
- 운영팀 정산 업무 시간 단축 -> 업무 효율성 향상

### **Angular 기반 + React 부분 렌더링 환경에서 동적 OG 태그 적용**
<!-- Angular 기반 애플리케이션에서 React로 점진적으로 마이그레이션 중인 가운데, Open Graph(OG) 메타 태그가 고정되어 있어 SNS 공유 시 랜딩의 각 서브 페이지에 맞는 OG 태그를 노출하는 데 문제가 있었습니다. 이에 **AWS CloudFront Function을 활용해 크롤러 요청 시 URL에 맞는 OG 태그가 포함된 HTML을 반환하도록 구성**하였고 이를 통해 **SEO 및 SNS 공유 최적화** 문제를 효과적으로 해결했습니다. -->

##### 문제 상황
Angular 기반 애플리케이션에서 React로 점진적으로 마이그레이션 중인 가운데, Open Graph(OG) 메타 태그가 고정되어 있어 SNS 공유 시 랜딩의 각 서브 페이지에 맞는 OG 태그를 노출하는 데 문제가 있었습니다. 이로 인해 SNS 공유 시 메타 태그가 적절히 반영되지 않는 문제가 발생했습니다.

##### 시도한 내용
React-Helmet과 SSR처럼 HTML을 미리 렌더링해주는 React-Snap을 테스트했으나, 프로젝트 구조상 적용이 어려웠습니다. 이로 인해 클라이언트가 아닌 서버 측에서 관리하는 방법을 모색하게 되었습니다. 그 과정에서 AWS의 CloudFront Function을 활용해 특정 URL 경로에 맞는 HTML을 반환하는 방식을 실험하며 동적 OG 태그 적용 가능성을 확인했습니다. AWS의 또 다른 솔루션인 Lambda@Edge와도 비교 테스트를 진행했으나, CloudFront Function이 약 1/6의 비용으로 비용 효율성이 높고 구현이 간단한 장점이 있어 최종적으로 선택했습니다.

##### 구현 내용
CloudFront Function은 URL 요청을 트리거로 동작하도록 설정했으며, 요청 URL 경로에 맞는 OG 태그가 포함된 HTML을 반환하도록 구성했습니다.

##### 성과 
- SEO 및 SNS 공유 최적화 문제 해결

### **서브 도메인별 사이트 맵 관리 및 제출**

##### 문제 상황
검색엔진에 서브도메인을 사용하는 사용자별 뉴스레터 아카이빙 페이지의 노출이 저조하다는 불만이 종종 접수되었습니다. 이는 사이트맵 구조 문제로 서브 도메인 페이지 색인 누락되어 있었으며, 실시간으로 추가되는 뉴스레터가 사이트맵에 자동으로 반영되지 않는 문제가 있었습니다.

#### **health-friends**

2020.01. ~ 2021.03.  

**주제**: 이용하고 있는 헬스장에서 함께 운동할 수 있는 친구를 매칭하는 서비스 입니다.

**개발**
- NextJs, Express 프레임워크로 구축하였습니다.
- Redux를 이용하여 상태관리를 하고 있고 Redux-Toolkit을 사용하여 불필요한 보일러플레이트 코드를 줄이고 Redux 사용 시, 필요한 라이브러리를 내장된 메들웨어를 통해 의존성을 줄였습니다.
- react-query를 통해 Store의 역할이 비대해 지는 것을 방지하고 데이터 업데이트 및 관리 및 lazy data등의 Server State를 관리하고 처음 Redux와 함께 사용했던 Redux-Saga를 제거하였습니다.
- 공통으로 사용하고 있는 커스텀 대화상자를 사용할 때 사용하는 컴포넌트 마다 state가 필요했던 기존 환경을 contextAPI와 react portal을 통해 global 모달로 리팩토링하였습니다.
- AWS EC2를 통해 배포하였고 Lamda를 사용해 S3이미지 업로드 시, 이미지 리사이징을 하여 이미지 용량을 줄이고 Cloud Front를 통해 캐싱된 이미지를 불러와 웹 로드 시간을 단축하였습니다.
- 디자인 시스템 구축
    - Atomic 디자인 시스템으로 재사용 가능한 작은 단위로 UI 컴포넌트들을 구성하여 효과적인 인터페이스 시스템을 구축하였습니다.
- TDD 환경 구축
    - Jest와 React Testing Libary를 사용하여 unit 테스트 환경을 구축하였습니다.
